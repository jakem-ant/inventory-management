Factory Inventory Management — Architecture

Full-stack demo for inventory, orders, demand forecasting, and spending analytics. A Vue 3 single-page app talks to a Python FastAPI service that serves filtered views over in-memory JSON data — no database, no auth, intended as a workshop reference implementation.

Data Flow

How a filter selection in the UI becomes a rendered chart or table.

  1. User changes a filter
    FilterBar.vue updates shared refs in the useFilters composable (warehouse, category, status, month). Views watch those refs.
  2. View calls the API client
    The active view (e.g. Dashboard.vue) invokes api.getDashboardSummary(filters). Filters equal to 'all' are stripped; the rest become query-string params.
  3. FastAPI routes the request
    main.py receives the request, FastAPI parses query params into typed arguments, CORS allows the cross-origin call from :3000.
  4. Endpoint filters in memory
    The handler reads the relevant list from mock_data.py (loaded from server/data/*.json at startup), applies sequential filters on a copy — never mutating the source — and computes any derived totals.
  5. Pydantic validates the response
    response_model on the route ensures the JSON shape matches the declared InventoryItem / Order / DemandForecast / BacklogItem model.
  6. Client stores raw data in refs
    The view assigns the response to a ref (e.g. allOrders, inventoryItems). Derived values — KPIs, chart series, grouped totals — live in computed properties so they only recompute when inputs change.
  7. Template renders
    Vue's reactivity propagates: tables, SVG charts, and metric cards update. Modal components (InventoryDetailModal, CostDetailModal, etc.) open against the same reactive data when a row is clicked.
